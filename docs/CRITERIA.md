# 採点基準は誰が決めたのか

**このベンチの177点のうち、外部の権威が要求しているのは 102点、残り 75点はわたしが決めた。**
その内訳を項目ごとに示す。

このシリーズは「参照解の外部化」——自作した参照解は較正でも敵対テストでも検査できない——を
掲げている。kanzei-bench は税関の事前教示回答、zeimu-bench は国税庁の質疑応答事例という
外部の権威が答えを持っている。**cad-bench は違う。**答えは spec から決定論で導出されるので
一意だが、「何を検査項目に選び、何点を配るか」はわたしの判断である。ここを開示する。

## 使った外部資料

| 資料 | 入手性 | 使い方 |
|---|---|---|
| 建築基準法施行令23条、法28条1項・2項 | e-Gov で無償 | L4 の法規判定の根拠。条文名を採点結果に出力している |
| 千葉県 照査項目チェックリスト（土木工事） | 千葉県サイトで無償・PDF | 「図面と計算が食い違わないか」型の検査の根拠 |
| Autodesk DXF Reference | 無償 | 形式の妥当性（L0）。製図の作法については何も言わない |
| **JIS A 0150（建築製図通則）** | **JSA 有償。未入手** | **穴。下記 C 群の根拠になるはずのもの** |

## A. 法令に直接の根拠がある — 39点（22%）

採点結果に条文名がそのまま出る。

| 検査 | 点 | 根拠 |
|---|---|---|
| 蹴上 ≤ 230mm | 5 | 令23条 |
| 踏面 ≥ 150mm | 5 | 令23条 |
| 階段の幅 ≥ 750mm | 5 | 令23条 |
| 和室 採光 ≥ 床面積の1/7 | 8 | 法28条1項 |
| 和室 換気 ≥ 床面積の1/20 | 4 | 法28条2項 |
| LDK 採光 ≥ 床面積の1/7 | 8 | 法28条1項 |
| LDK 換気 ≥ 床面積の1/20 | 4 | 法28条2項 |

ただし採光補正係数（令20条）を1と仮定した簡略モデルである。実務の判定には使えない。

## B. 千葉県チェックリストが要求している型 — 63点（36%）

千葉県のものは**土木**の照査項目で、建築の平面図を直接は扱わない。
それでも「図面と、その裏にある計算・申告が食い違っていないか」という**型**は共通で、
本ベンチの検査の多くはその型に当てはまる。対応を1件ずつ示す。

| 検査 | 点 | 対応する照査項目 |
|---|---|---|
| 壁面が芯から±60mmに乗っている（壁厚120の担保） | 5 | **4-10**「設計計算書の結果が正しく図面に反映されているかの確認 …**・壁厚**」— 壁厚が名指しで挙がっている |
| 図面に表示される寸法値が仕様と一致する | 10 | **4-5**「構造図の基本寸法、座標値、高さ関係は照合されているか」／**4-10** |
| DIMENSIONで作図されている（専有の作図ブロックに中身がある） | 10 | **4-7**「図面が明瞭に描かれているかの確認（構造物と寸法線の使い分けがなされているか）」 |
| 寸法を線分＋文字で偽装していない | 5 | **4-7** 同上 |
| 各室の面積が正しく計算・記入されている | 10 | **5-1**「数量計算に用いた数量は図面の寸法と一致するかの確認」 |
| 1階の床面積の合計が正しく記入されている | 3 | **5-1** 同上 |
| 段板の本数が段数と整合する | 5 | **4-11**「形状寸法、使用材料及びその配置は計算書と一致しているかの確認」 |
| 作図された段板のピッチが申告の踏面と一致する | 5 | **4-11** 同上 |
| 全ての開口が壁の中に収まっている | 5 | **4-11** 同上 |
| 階段の作図が階段室の内法に収まっている | 5 | **4-14**「構造物の施工性に問題はないか」 |

**T004 の建具表（`<dxf>.schedule.json`）は 4-11 の「計算書」に相当する。**
模型が自分で決めた寸法を申告させ、図面と突き合わせる構造は、この照査項目の写しである。

## C. わたしが決めた — 75点（42%）

外部の裏付けが取れなかったもの。**点を配ってはいるが、配点の根拠はわたしの判断である。**

| 検査 | 点 | 状況 |
|---|---|---|
| DXFとして開ける | 10 | Autodesk DXF Reference は形式を定めるが「開けたら何点」は定めない |
| 必須レイヤが定義されている | 5 | `spec.json` が要求している＝わたしが要求している |
| 0レイヤ直置きがない | 5 | 実務では広く守られる慣行だが、**成文の裏を取っていない** |
| 壁の線を描けている（被覆率） | 10 | 被覆率という指標自体がわたしの発明 |
| WALLレイヤに余計な線がない | 5 | 同上 |
| 開口部で壁が欠き込まれている | 6 | 建築製図の常識だが根拠は JIS A 0150 側にあるはず |
| 開口部に建具が作図されている | 4 | 同上 |
| 室名が正しい室の中に記入されている | 10 | 同上 |
| 通り芯が正しい位置に引かれている | 5 | 同上 |
| 通り芯符号が記入されている | 5 | 同上 |
| モデル空間が実寸mm（1:1） | 5 | 5-3「縮尺は図面に整合しているか」が近いが、土木の横断図の話 |

## この仕分けで分かったこと

**千葉県チェックリストに、建築の製図作法を指す語は一つも出てこない。**

```
通り芯 0件   室名 0件   建具 0件   レイヤ 0件   線種 0件   文字高 0件
整合 8件   寸法 4件   一致 2件   壁厚 1件   面積 1件
```

一方で「整合」が8件。**この資料は「図面と計算が食い違わないか」を問う文書であって、
「図面が製図の作法に従っているか」を問う文書ではない。**

つまり本ベンチの採点器は、**性格の違う2つを混ぜて177点にしている。**

- **図面と計算・申告の整合**（A + B = 102点）— 外部が要求している。ここは自信を持って報告できる
- **建築製図の作法**（C = 75点）— わたしの意見。JIS A 0150 を買うまで裏付けられない

L5（文字高さ・線種・符号の丸囲み・図面枠）を点数化していないのも同じ理由である。
これまで README には「JIS の解釈を採点器に固定する自信が無かったから」と書いていたが、
正確には**根拠となる規格を持っていないから**であり、C 群の11項目もまったく同じ立場にある。
**L5 だけを点数外にしているのは一貫していない。**

## 直すとしたらどうするか

1. **JIS A 0150 を買う**（JSA、数千円規模）。C 群と L5 の大半に成文の根拠が付く。
   買った時点で、C 群のうち何点が実際に裏付けられたかを本ファイルに追記する
2. 裏付けが取れなかった項目は**点数から外して助言に落とす**。
   現在の 177点は、そのとき 102点＋αに縮む可能性がある
3. **公開時は A/B/C の内訳を必ず併記する。**
   総合点だけを出すと、42%がわたしの意見であることが読み手に伝わらない

## 参照解そのものについて

答え（reference/reference_t00N.dxf）は `bench/build_ref.py` が spec から決定論で組む。
**壁 = 壁芯を ±(壁厚/2) で膨らませて union した領域、描くべき線 = (その領域 − 開口) の境界。**
この定義自体は作図者の癖に依存しないので、答えの一意性は担保されている。
問題は答えではなく、**答えのどの側面を何点で測るか**にある。
